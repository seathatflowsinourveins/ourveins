==== Failure mode (Tier-B sub-class — line-continuation chains) ====

Bash line continuation `\<newline>` is a SHELL-PARSE-time construct: shell consumes the `\<newline>` and joins lines. But CC presents the PRE-shell-parse cmd literal to PostToolUse hooks. Hook receives:

```
git -C path add -- file && \<newline>git -C path commit -F msg
```

Where `\<newline>` is 2 literal chars: single backslash (chr(92)) + newline (chr(10)).

After Ship I's `re.split(r"\s*(?:&&|\|\||;)\s*", cmd.strip())`:
- Segment 1: `git -C path add -- file`
- Segment 2: `\<newline>git -C path commit -F msg`

`seg.strip()` removes trailing `\n` whitespace but leading `\` is NOT whitespace → preserved. Result: segment 2 starts with `\` → `seg.startswith("git ")` False → SKIP → `git_verb_matches` returns False.

Ship I's rtk-prefix strip doesn't catch this because `\` isn't the `rtk ` prefix.

==== Fix: 1 surgical Edit at _guard_base.py:368 ====

Pre-process cmd to collapse `\<whitespace>` line continuations BEFORE re.split:

```python
+    # Collapse Bash line continuations `\<newline>` to single space (Wave 130 Fire 3
+    # Tier-B defense-in-depth — `&&` chain with `\<newline>` continuation produces
+    # segment-2 starting with literal `\` non-whitespace breaking segment prefix
+    # check; CC presents pre-shell-parse cmd literal so backslash-newline survives
+    # to hook-input. Sister to RTK-strip below for compound-chain coverage).
+    cmd = re.sub(r"\\\s*\n\s*", " ", cmd)
     for seg in re.split(r"\s*(?:&&|\|\||;)\s*", cmd.strip()):
```

Regex `\\\s*\n\s*` matches: literal `\` + optional whitespace + literal `\n` + optional whitespace. Replaces with single space. Subsequent `&&` split sees clean segments.
