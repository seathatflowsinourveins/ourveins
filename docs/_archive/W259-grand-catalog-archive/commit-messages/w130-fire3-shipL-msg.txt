==== Adversarial bypass Ship K introduced (codex T3 catch) ====

Codex T3 verdict at `.claude/state/codex_review_HEAD_9d6f2383.txt`:
> Bash removes an unquoted backslash-newline with no delimiter before tokenization, so commands like `git comm\<newline>it -m msg` or `gi\<newline>t push origin main` execute as `git commit` / `git push`. This preprocessor instead replaces the continuation with a space, turning those same commands into `git comm it` / `gi t push` for `git_verb_matches`, so the helper can return false even though Bash will run the protected git operation. Given this helper is in the shared guard base for commit/push gates, an adversarially formatted command can still bypass gitleaks/codex hook detection.

Severity: HIGH (file=`.claude/hooks/scripts/_guard_base.py` line=372). Confidence: 0.86.
next_steps: "Change the continuation normalization to preserve Bash concatenation semantics and rerun the git verb matching smoke tests with token-splitting bypass cases."

==== Fix: 1 surgical Edit at _guard_base.py:368 ====

```diff
-    cmd = re.sub(r"\\\s*\n\s*", " ", cmd)
+    cmd = re.sub(r"\\\r?\n", "", cmd)
```

Bash semantic: `\<newline>` is DELETED (not replaced with space). So `git comm\<newline>it` becomes `git commit` (concatenated, no space). Ship L matches Bash exactly.
