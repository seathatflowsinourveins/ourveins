## Bug 2: hookify hook spam → noise on every PreToolUse/PostToolUse

Just-installed `hookify@claude-plugins-official` plugin (Wave 133 Fire 2 era)
was spamming `Hookify import error: No module named 'core'` on every
PreToolUse:Read / PostToolUse:Read / PreToolUse:Bash / PostToolUse:Bash
because `pretooluse.py` line 13-15 reads `CLAUDE_PLUGIN_ROOT` env var to
add to sys.path BEFORE `from core.config_loader import load_rules` — but
the env var isn't propagating to the Python subprocess on this
Claude Code 2.1.138 / Windows runtime.

Cache files exist correctly:
- `.claude/plugins/cache/claude-plugins-official/hookify/0e7bbeafaebc/core/__init__.py`
- `.claude/plugins/cache/claude-plugins-official/hookify/0e7bbeafaebc/core/config_loader.py`
- `.claude/plugins/cache/claude-plugins-official/hookify/0e7bbeafaebc/core/rule_engine.py`

But import fails because `sys.path.insert(0, PLUGIN_ROOT)` is no-op when
`PLUGIN_ROOT` is None/empty. The hook then graceful-degrades via try/except
exit-0 + system-message error — hence the spam.

Fix: disable hookify plugin in `enabledPlugins` (`true` → `false`). Plugin
cache stays present (hard-gate stays green), hooks don't fire = no spam.
Reversible via flip back to `true` once upstream fixes self-location OR CC
runtime sets CLAUDE_PLUGIN_ROOT correctly.

Note: this fix only takes effect on NEXT eee launch — current session has
hookify hooks already loaded; the spam will continue until restart.

Forward-ref upstream issue:
- File at `https://github.com/anthropics/claude-plugins-official/issues` —
  request `pretooluse.py` self-locate via `__file__`-derived path as fallback
  when `CLAUDE_PLUGIN_ROOT` env not set. 5-line patch:
  ```python
  if not PLUGIN_ROOT:
      PLUGIN_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
  ```
- Apply same fix to all 4 hooks: pretooluse.py / posttooluse.py / stop.py /
  userpromptsubmit.py.
