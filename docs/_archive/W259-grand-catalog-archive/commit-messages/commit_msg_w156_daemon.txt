refactor(infra): Wave 156 — convert aperant poller + rotation planner to daemon mode

Resolves the constant `Z:\venvs\claude\Scripts\python.exe` spawning surfaced by
the operator. Root cause was two Windows Scheduled Tasks (`EEE-Aperant-Poller`
60s, `EEE-Rotation-Planner` 5min) firing `--once` invocations — spawn-per-tick
churn ≈ 72 python.exe spawn-die events per hour.

# Before / After

- BEFORE: 0 long-lived daemons + ~60 short-lived poller spawns/hr + ~12 planner
  spawns/hr = ~72 spawn-die events/hr observable as constant python.exe flicker
  in Task Manager.
- AFTER: 2 long-lived `--start` daemons (1 poller + 1 planner) — each launches
  ONCE at boot (or at -Install time via Start-ScheduledTask), polls internally
  on its own loop. spawn-die events/hr → ≈ 0. Polling cadence preserved
  (60s poller / 5min planner) via existing `--interval-seconds` flag.

Daemons stable + verified writing JSONL post-deploy. Poller still emits one
JSONL row per account per 60s tick — observable signal unchanged.

# Discovery

The fix is a one-flag rewire because the daemon-mode is ALREADY CODED in both
target scripts:
- tools/aperant_rate_limit_poller.py:339-426 — `--once` / `--start` / `--stop`
  / `--interval-seconds`; --start branch implements PID file at L381 + stop
  sentinel polled mid-loop at L416 + `interval = max(15, args.interval_seconds)`
  floor at L414 + finally cleanup at L423-426. F-2 logic at L382-386 proactively
  clears prior `.stop` sentinel before entering loop (eliminates restart race).
- tools/eee_account_rotation_planner.py:217-240 — same --once/--start contract.

Old Wave 94 installer wired `--once`. This Wave 156 ship rewires to `--start`
with `-AtStartup` trigger + `-ExecutionTimeLimit (New-TimeSpan -Days 0)` (PT0S
= unlimited per Microsoft Learn) + `-RestartCount 3 -RestartInterval 1min` for
crash recovery.
