## Bug + fix

### Pre-fix (Wave 121 Ship 2 + Wave 119 Ship 5 scaffold)

`evals/deepeval/test_smoke.py:32-35` had INVERTED cost-guard semantics:

```python
@pytest.mark.skipif(
    os.environ.get("DEEPEVAL_SKIP_LIVE", "0") == "1",
    reason="set DEEPEVAL_SKIP_LIVE=0 to run live LLM-as-judge eval against CPA",
)
```

Default `DEEPEVAL_SKIP_LIVE=0` (or unset) → `"0" == "1"` is False → DO NOT SKIP → LIVE RUNS.
Result: `pytest evals/deepeval/` BURNS Anthropic tokens via CPA `eee-fleet-key-eval` by
default. README at line 21 falsely claimed "skip live by default" but line 34 confirmed
LIVE was actually the default (internal inconsistency).

Fire 19 GPT-5.5 cross-model audit (conf=0.88) identified this as P1-2 TOKEN-BURN RISK.

### Post-fix (W134-F22-A)

```python
@pytest.mark.skipif(
    os.environ.get("DEEPEVAL_ENABLE_LIVE", "0") != "1",
    reason="set DEEPEVAL_ENABLE_LIVE=1 to run live LLM-as-judge eval against CPA (spends Anthropic tokens via eee-fleet-key-eval). Token-safe default: SKIPPED.",
)
```

Default `DEEPEVAL_ENABLE_LIVE=0` (or unset) → `"0" != "1"` is True → SKIP → token-safe.
Opt-in `DEEPEVAL_ENABLE_LIVE=1` → `"1" != "1"` is False → DO NOT SKIP → live runs.
