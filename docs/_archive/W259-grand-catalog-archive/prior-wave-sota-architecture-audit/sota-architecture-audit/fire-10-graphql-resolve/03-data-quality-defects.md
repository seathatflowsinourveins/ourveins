## Fire 5 baseline-extraction bug retrospective

### What went wrong

Fire 5 baseline extraction (`_repo-baseline.txt`) was generated by parsing kit manifest
descriptors. The parser likely:
1. Tokenized on whitespace
2. Filtered to tokens containing `/`
3. Treated each such token as a candidate repo slug

Without filtering for the `^[a-zA-Z0-9_-]+/[a-zA-Z0-9_.-]+$` slug pattern, file-paths
and phrases with `/` slipped through.

### Impact on Fire 5/6/8/9 coverage % accounting

- **Inflated baseline**: 44 entries marked as "unreachable A4" repos
- **Inflated denominator**: 640 cumulative baseline likely includes 37 non-repo entries
- **TRUE baseline**: 640 - 37 = **603** if we exclude data-quality defects

### Fix-forward path

**Fire 11 candidate**: re-extract baseline with strict slug-pattern filter:
- Filter `_repo-baseline.txt` via `grep -E '^[a-zA-Z0-9_-]+/[a-zA-Z0-9_.-]+$'`
- Re-run all coverage % calculations against filtered count
- Document the 37 defects as historical-baseline-error in a retrospective MD
