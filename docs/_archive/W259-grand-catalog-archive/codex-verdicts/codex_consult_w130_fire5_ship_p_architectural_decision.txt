==== THE ARCHITECTURAL TENSION ====

CC's `if:` matcher is string-prefix-and-wildcard, NOT shell-aware. Both Round 1 and Round 2 are symptoms of this fundamental mismatch:
- Round 1 (Ship H): permissive Tier-A `Bash(*git commit *)` admits text-only substring matches (false positives)
- Round 2 (Ship O): restrictive Tier-A `Bash(git commit *)` rejects shell-prefixed commands like env-var assignments + `env` wrapper (false negatives)

Pattern shape #2 examples are common shell idioms in CI/scripts/operator workflows:
- `GIT_AUTHOR_NAME='Build Bot' git commit -m 'auto'`
- `GIT_COMMITTER_DATE='...' git commit -am msg`
- `env GIT_TRACE=1 git push`
- `GIT_SSH_COMMAND='ssh -i key' git push`
- `HOME=/tmp git push`

==== THREE ARCHITECTURAL OPTIONS ====

**Option A (Tier-B-only — codex's preferred prescription)**:
- Drop Tier-A `if:` filter on the 16 affected hook entries (replace with permissive `Bash` matcher OR no `if:`)
- Strengthen Tier-B `git_verb_matches` in `_guard_base.py` with:
  - env-var-assignment prefix stripping: `re.sub(r'^([A-Z_][A-Z0-9_]*=\S*\s+)+', '', seg)` BEFORE `git ` check
  - `env [args] ` wrapper stripping: `re.sub(r'^env(\s+(--[\w-]+(=\S+)?|[A-Z_][A-Z0-9_]*=\S*))*\s+', '', seg)`
- Add smoke test for both bypass classes (text-only + env-prefix)
- Cost: ~30-50 LOC in `_guard_base.py` + ~10 LOC test additions
- Trade: 4 scripts now spawn Python on EVERY Bash command (not just git-shaped ones). Cost ~10-50ms Python startup per non-git Bash. Mitigation: Tier-B early-bails on non-git segments (line 372 `continue`).

**Option B (Combinatorial Tier-A patterns)**:
- Retain Ship O's 16 patterns
- Add 16 MORE patterns covering env-prefix shapes: `Bash(*=* git commit *)`, `Bash(env * git commit *)`, `Bash(*=* rtk git commit *)`, etc.
- BUT this still misses unanticipated wrapper forms (e.g., `nice git push`, `time git commit`, `taskset 0x1 git commit`)
- Combinatorial explosion — pattern count doubles; still incomplete coverage
- Cost: ~16 more `if:` entries (32 total) + smoke-test expansion

**Option C (REVERT Ship O + ACCEPT-WITH-DOC at Ship H state)**:
- `git revert 57fbad8` restores Ship H leading-wildcard `Bash(*git commit *)` form
- Net trade: medium-severity known-residual (substring false-positive) > high-severity known-residual (env-prefix false-negative)
- BUT Round 1 was already medium severity AND is the SAME class codex caught
- Per `closed-loop-recursive-narrowing.md` Outcome A: "concrete verification: a passing probe/test demonstrates the residual risk is actually bounded" — Ship H has no concrete verification of the substring false-positive being bounded
- Per `closed-loop-recursive-narrowing.md` Outcome A: "severity downgrade in evidence: codex's last-round severity field landed at `low` or `info` after the fix iterations" — Ship H severity stayed at medium (didn't downgrade)
- Outcome A severity gate FAILS for Option C revert path

**Option D (MANUAL-OVERRIDE keep Ship O state)**:
- Keep Ship O's 16 patterns as-is
- Document env-prefix bypass as known-residual operator-accepted high-severity risk
- Add `MANUAL-OVERRIDE` marker per `closed-loop-recursive-narrowing.md` Outcome C
- Mitigations: (a) eee runtime doesn't currently use env-prefix git invocations in any sss/eee scripts; (b) Tier-B Python startup cost on non-git Bash would still be paid by Option A
- Trade: known high-severity gap accepted explicitly; future incident class
