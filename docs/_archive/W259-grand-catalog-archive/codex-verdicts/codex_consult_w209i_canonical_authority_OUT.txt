**Verdict**

Your list is mostly right, but I would tighten “canonical”:

1. **MCP: YES, with corrections.** Canonical is now the `modelcontextprotocol` org/spec and official SDKs. `mark3labs/mcp-go` is no longer canonical; `modelcontextprotocol/go-sdk` exists and is official, maintained with Google. `jlowin/fastmcp` is useful, not canonical. `modelcontextprotocol/servers` is official/reference-ish, but the **registry** is now the discovery authority.
2. **ACP: YES, but narrower.** Canonical is `agentclientprotocol/agent-client-protocol`, originally Zed-led, now its own org. It is editor/IDE ↔ coding-agent protocol, not general agent-to-agent.
3. **AI safety: your tools are not the canonical standard layer.** Canonical authority for prompt injection defense is **OWASP LLM Top 10 2025**, **OWASP MCP Top 10**, and **NIST AI RMF GenAI Profile**. PurpleLlama/Prompt Guard, NeMo Guardrails, Guardrails AI, LLM Guard, Presidio, garak are implementation/evaluation tools.
4. **OpenTelemetry GenAI: YES, but still “Development,” not stable.** Use it, but version-pin and expect churn.
5. **Identity/audit: mostly YES.** SPIFFE/SPIRE and in-toto are CNCF graduated. Sigstore is **OpenSSF graduated**, not CNCF. SLSA is OpenSSF and canonical for build provenance.

**Missing / Competing Standards**

Add these to the W209 authority map:

- **A2A / Agent2Agent**: Google-originated, Linux Foundation hosted. This is the main competing/complementary standard for **agent-to-agent**, whereas MCP is model/tool-context and ACP is editor/agent.
- **AG-UI**: emerging agent ↔ frontend/user-interface protocol. Nice-to-have unless you build agent UIs.
- **JSON-RPC 2.0**: base protocol for MCP and ACP.
- **JSON Schema / OpenAPI Schema subset**: practical convergence layer for tool schemas.
- **OAuth 2.1 / OIDC / RFC 8707-style resource indicators**: relevant for remote MCP auth.
- **W3C Trace Context**: must-have propagation substrate under OTel.

**Deprecations / Supersessions Since 2025**

- **MCP HTTP+SSE transport is deprecated as of MCP protocol version `2025-03-26`.** Current MCP standard transports are `stdio` and **Streamable HTTP**. The spec says Streamable HTTP “replaces” HTTP+SSE from protocol version `2024-11-05`; back-compat may keep old SSE endpoints.
- **OpenTelemetry GenAI changed materially after v1.36.0.** Current docs mark GenAI semconv as **Development** and recommend `OTEL_SEMCONV_STABILITY_OPT_IN=gen_ai_latest_experimental` for latest behavior.
- **MCP Go SDK:** use `modelcontextprotocol/go-sdk`, not `mark3labs/mcp-go`, for canonical installs.
- **Sigstore classification:** OpenSSF graduated, not CNCF graduated.

**MUST-INSTALL For Fresh Claude Code SOTA Runtime**

Must-install / must-conform:

1. **MCP spec + official SDKs**: local `stdio`, remote Streamable HTTP.
2. **MCP Inspector / conformance tooling** for server validation.
3. **JSON Schema validation** for tool input/output contracts.
4. **JSON-RPC 2.0** protocol handling discipline.
5. **OpenTelemetry SDK + GenAI semconv pinned version**.
6. **W3C Trace Context propagation**.
7. **OWASP LLM Top 10 2025 + OWASP MCP Top 10 controls**.
8. **Sigstore + in-toto attestations + SLSA provenance** for install artifacts.
9. **Secret scanning / provenance gates** around installs and commits.
10. **ACP** only if exposing Claude Code through editor/IDE clients.

Nice-to-have:

- **A2A** for cross-agent networked collaboration.
- **SPIFFE/SPIRE** if you run remote services/workloads, not necessary for local-only runtime.
- **AG-UI** if building a frontend agent surface.
- **PurpleLlama / garak / NeMo Guardrails / LLM Guard / Presidio** as defense/eval components, not standards.

**Cross-Vendor Tool Calling**

Yes, there is practical convergence on:

- tool/function `name`
- natural-language `description`
- parameters/input schema shaped like **JSON Schema**
- tool-call result loop

But it is **not fully portable JSON Schema**:

- OpenAI: function tools defined by JSON Schema; `strict: true` enforces schema subset.
- Anthropic: tools use `input_schema` JSON Schema.
- Google Gemini: function declarations use a supported subset of OpenAPI/JSON-schema-like schema; newer structured outputs expanded JSON Schema support.
- Mistral: function calling uses JSON schema.

Production rule: keep provider-specific schema adapters and app-side validation.
