55: ## Why this rule exists
56: 
57: The prior default was "wait for n≥2 before codifying" (parent cycle-273 close report), which protected against over-specification from small samples. But three consecutive n=1 codifications (parent cycle-296, 318, 319) have all held against subsequent applications without revision — the n≥2 bar was a proxy for "avoid premature codification" when the root metric is **cost-per-miss**.
58: 
59: Codifying too early costs LOC in a reference file (~50-150 LOC typical). Codifying too late costs re-derive time at each future application. For patterns where re-derive is cheap (~minutes), waiting for n=2 is effectively free. For patterns where re-derive is expensive (>15 min), every "wait for n=2" burns 15+ min on the next application — and if frequency is several per month, the wait dominates.
