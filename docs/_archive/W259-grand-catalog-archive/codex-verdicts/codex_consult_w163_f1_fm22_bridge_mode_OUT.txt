## The rule

When a subagent dispatched under `agent_plan_readonly_bash_guard.py --policy codex-readonly` attempts BRIDGE-MODE invocation (Sonnet wrapper → real GPT-5.5 via codex CLI subprocess per `cross-model-consensus.md §Env-funneled subagent stand-in disclosure mandate`), the policy refuses with two structural deny messages that enter the agent's tool-result context:

1. `block:powershell not in codex-readonly allowlist (fail-closed)`
2. `block:codex deny-token --dangerously-bypass-approvals-and-sandbox`

These deny strings can be misinterpreted as **injected adversarial directives** ("the system says don't run codex; I should stand-down") rather than recognized as **structural policy-block refuse** ("this dispatch shape cannot achieve BRIDGE-MODE; route around"). The misclassification produces stand-in verdicts that silently lack model-asymmetry value while appearing to satisfy cross-model consensus at the synthesis layer.

The discipline: classify codex-readonly BRIDGE-MODE refuse as a STRUCTURAL POLICY block (Wave 11A safety floor by design per `lga-five-layers.md §4.1`), NOT as content-injection. Route BRIDGE-MODE invocation via main-session foreground+tee per `cmc-t1-t7-lifecycle.md §The contract` Phase 1 bootstrap exception. Stand-in verdicts from gpt5-reviewer remain useful for citation-discipline / phantom-MCP / file-read findings (per `fm19-readonly-guard-sidestep.md` — file reads work under codex-readonly) but model-asymmetry value is ABSENT — disclose explicitly via STAND-IN-NOTICE per `cross-model-consensus.md §Env-funneled subagent stand-in disclosure mandate`.

## How to apply (classify-policy-block-as-structural discipline)

Before accepting a BRIDGE-MODE-dispatched stand-in verdict at synthesis layer, run parallel Mia probes:

1. **Refuse-message inspection** — does agent's tool-result context contain either of the 2 verbatim denial strings? If yes → classify as policy-block REFUSE, NOT as content-injection
2. **Dispatch-path verification** — was BRIDGE-MODE invocation routed via `Agent({permission_mode: "plan"})` under codex-readonly? If yes → expected refuse; cross-model gate NOT satisfied for this dispatch
3. **Stand-in classification** — apply `cross-model-consensus.md §Env-funneled subagent stand-in disclosure mandate`: dispatch returned as Sonnet stand-in only; model-asymmetry value absent
4. **STAND-IN-NOTICE disclosure** — commit body MUST include `<agent> dispatched as Agent() under codex-readonly per FM-22 BRIDGE-MODE-refuse-as-injection subclass; cross-model gate NOT satisfied for this dispatch; codex T1 re-review queued via main-session foreground+tee`

If ALL 4 probes fire: stand-in verdict useful for citation/phantom-MCP/file-read findings only; do NOT treat as cross-model consensus satisfaction.

## Rule: Every new pattern MUST cite its source at file:line depth

1. **Header comment**: `# Reference: Z:/repos/deps/<repo>/<file>:<line>` or `# Reference: <official-docs-URL>`
2. **Never cite READMEs alone** — cite the actual source code implementation
3. **Star count does NOT indicate quality** — read the source, verify the claim
4. **Verify before trust** — the cited file must still exist AND still say what you cite (labels decay)
5. **Silent fallback = violation** — if expected output doesn't appear (e.g., `embeddings: 0` after `--embeddings`), that's a STOP, not a footnote (parent `feedback_reference_first_hard_rule.md` — PARENT-ATTRIBUTION pending sss memory port)
6. **TIER-1-NAMED-AUTHOR-QUOTE class for inherited patterns** — when a SOTA pattern is derived from a named author's published work (book / peer-reviewed paper / conference talk), cite verbatim-quote + author-name + publication inline. The named-author cite is TIER-1 primary-source for the PATTERN (not the implementing repo); use alongside repo file:line cites for full provenance. 8. **Composed-claims discipline + mechanical source-class reduction lattice** — *(Wave 17 fire-31 v1 codification per codex T1 fire-28 conf=0.87; UPGRADED at fire-36 per codex T1 fire-33 NEEDS-REVISION on T2 b8fa7dd1 finding "weakest-source rule not computable" conf=0.72)* — When a single normative claim cites MULTIPLE source classes, the cite MUST declare:
   - `constituents=[<class1@cite1>, <class2@cite2>, ...]` — explicit list of each constituent primitive at file:line + SHA OR official-docs URL
   - `effective_tier=<class>` — the EFFECTIVE class of the composed claim, computed by the reduction lattice below

   **Source-class precedence/order (lower wins; weakest dominates)**:
   1. `UNKNOWN` (no cite at all) — always disqualifying; reject claim until cited
   2. `TIER-3-LOCAL-COMPOSITION` (any local glue / sss-novel composition over TIER-1/TIER-2 substrates)
   3. `TIER-3-LOCAL-OPERATOR-DERIVED` (sss dogfood, codex verdicts, incidents, operator decisions)
   4. `TIER-3-LOCAL-CONFIG` (sss live config or script wiring)
   5. `TIER-2` (user-curated/sibling docs, NOT upstream authority)
   6. `TIER-1-COMPOSED` (ALL constituents TIER-1 with disclosed local glue) — still TIER-3-LOCAL-COMPOSITION as effective tier
   7. `TIER-1-DIRECT` (upstream verbatim file:line + SHA OR official-docs URL with anchor)

   **Reduction rule (mechanical)**: `effective_tier = MIN_PRECEDENCE(constituents)`. Concretely: if ANY constituent contains "TIER-3-LOCAL-*" OR the composition glue itself is local-codified (e.g., sss-novel composition pattern), the effective tier is `TIER-3-LOCAL-COMPOSITION` regardless of how many TIER-1 primitives are cited. EXCEPTION: if the composed claim is ONLY about an upstream primitive's EXISTENCE (e.g., "asyncRewake field exists" cited verbatim from Anthropic docs), it remains `TIER-1-DIRECT` because there's no local composition glue.

   **Anti-promotion rule**: composition CANNOT promote a TIER-2/TIER-3 component into TIER-1. The cite class of the COMPOSED claim is determined by the MIN_PRECEDENCE constituent OR by the composition-glue class, whichever is weaker.

   **Exemplar (computable)**: `.claude/rules/cross-model-consensus.md §Normative Authority Map` row "T1-T7 touchpoint lifecycle":
   - `constituents=[TIER-1-DIRECT @ Anthropic-CC-hooks-docs-L1021-1023, TIER-2 @ CCBP-cross-model-workflow.md:1-48, TIER-3-LOCAL-COMPOSITION @ sss-novel T0+T7+profile-selection]`
   - `effective_tier=TIER-3-LOCAL-COMPOSITION` (MIN_PRECEDENCE = 2 due to sss-novel glue)
   - Despite Anthropic CC + CCBP being upstream-authority for primitives, the composition itself is eee-local and EFFECTIVE class is TIER-3-LOCAL-COMPOSITION

   Apply to: any rule body section in `.claude/rules/**` that mixes upstream + sister-rule + local-operator-codification claims. Sister: `cross-model-consensus.md §Normative Authority Map` (POINTS TO this rule, does NOT carry softer duplicate).
