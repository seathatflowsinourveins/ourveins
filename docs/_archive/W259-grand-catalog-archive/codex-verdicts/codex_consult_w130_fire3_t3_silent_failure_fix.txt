## Three fix options

### OPTION A: Widen `if:` matcher to substring patterns

Edit `.claude/settings.json` PostToolUse[0] entries [0]+[1]+[2]+[3]:
```diff
-    {"command": ".../codex_postcommit_review.py", "if": "Bash(git commit *)", ...},
-    {"command": ".../codex_postcommit_review.py", "if": "Bash(git -C * commit *)", ...},
-    {"command": ".../codex_prepush_review.py", "if": "Bash(git push *)", ...},
-    {"command": ".../codex_prepush_review.py", "if": "Bash(git -C * push *)", ...},
+    {"command": ".../codex_postcommit_review.py", "if": "Bash(*git commit *)", ...},
+    {"command": ".../codex_postcommit_review.py", "if": "Bash(*git -C * commit *)", ...},
+    {"command": ".../codex_prepush_review.py", "if": "Bash(*git push *)", ...},
+    {"command": ".../codex_prepush_review.py", "if": "Bash(*git -C * push *)", ...},
```

**Pros**: catches rtk-prefix AND heredoc-prefix; preserves rtk token-saving; minimal LOC (4 edits).
**Cons**: leading `*` may match unintended cmds containing "git commit" as substring (e.g., `echo "git commit ..."`); CC `if:` glob support for leading `*` is uncertain.

### OPTION B: Configure rtk to skip git-rewrite

`rtk hook claude --help` shows `--skip-env` exists but no `--skip-git`. Would need rtk upstream config support OR replacing rtk wrapper with conditional logic.

**Pros**: preserves clean `if:` matcher semantics.
**Cons**: requires understanding/extending rtk upstream config; not currently supported per `--help` output.

### OPTION D: Remove rtk hook from PreToolUse[6][6]

Edit `.claude/settings.json` to delete the rtk entry from PreToolUse[6].hooks array.

**Pros**: cleanest fix — restores original cmd flow; rtk says "no hook installed" via its own self-diagnostic suggesting rtk's state is already broken.
**Cons**: loses rtk's 80% token-saving on Bash output (Wave 118 Ship A2 install rationale).
