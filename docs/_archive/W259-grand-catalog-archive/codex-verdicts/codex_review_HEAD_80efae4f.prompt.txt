+### Teammate vs subagent — different primitives
+
+| | Subagent (Agent tool) | Teammate (TeamCreate) |
+|---|---|---|
+| Context | Isolated fork; inherits briefer | Full fresh window + CLAUDE.md + MCPs + skills |
+| Cost | Cheap (context hand-off only) | Expensive (full session boot per teammate) |
+| Use when | Short investigation/research/audit tasks | Multi-hour parallel implementation across independent surfaces |
+| Coordination | Parent holds state | Shared TaskList + agreed data contract |
+| Lifecycle hooks | SubagentStart/SubagentStop | TeammateIdle/TaskCreated/TaskCompleted |
+
+### Canonical Command → Agent → Skill pattern
+
+When spawning a 3-teammate team, split by primitive not by domain:
+1. **Command Architect** — builds `/command.md` entry point with `model: haiku` + Agent-tool + Skill-tool invocations
+2. **Agent Engineer** — builds `agents/agent-name.md` with `tools: [Bash]` or similar, preloads a skill via `skills:` frontmatter, `maxTurns: 3` for scoped work
+3. **Skill Designer** — builds `skills/skill-name/SKILL.md` with `reference.md` (templates) + `examples.md` (I/O pairs), `user-invocable: false` for agent-only skills
+
+All three spawn **in parallel** (per agent-teams-prompt.md:58 — "independent components only need to agree on data interface").
