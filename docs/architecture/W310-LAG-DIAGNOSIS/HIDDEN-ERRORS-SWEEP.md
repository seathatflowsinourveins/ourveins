## Cross-cutting analysis

The recurring fault class is **state drift between three sources**:

1. **Documentation claim** (CLAUDE.md / CLAUDE.local.md / `docs/architecture/W*`),
2. **On-disk config** (`.claude/settings.json` / `.mcp.json` / NSSM `sc qc`),
3. **Live service behavior** (HTTP probe + log tail).

Findings #4 (autocompact env), #7 (graphiti/FalkorDB), #5 (disabled MCP blocks), #15 (stale doc citations)
all share this shape — the docs were updated but the on-disk state was not, OR vice versa.
**Recommendation**: add a SessionStart hook that diffs the documented claims against live state
(`scripts/state-drift-audit.py`) and emits a structured `:disabledMcpjsonServers ⊆ .mcp.json` invariant check,
`CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` doc-vs-env check, `enabled ⊆ installed` plugin check.

Findings #1 (CUDA crash-loop) and #2 (cognee LLMAPIKeyNotSetError) are urgent because
they're silently degrading inference and memory capacity — both services show `Running` to NSSM
but emit only errors. **NSSM `Status` is not a meaningful health signal**; service-specific
HTTP probes ARE. Move from "is process alive?" to "is service answering correctly?".
