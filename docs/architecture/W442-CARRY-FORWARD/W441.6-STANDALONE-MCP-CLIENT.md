# W442 Carry-Forward: Standalone MCP-Client Wiring for v23 CLI

**Origin**: W441.6 codex r2 REVISE
**Wave deferred to**: W442
**Blocker**: Standalone Node CLI has no path to inject mcpClient → A5 deepwiki + A6 repomix angles always skip → ≥3-angle convergence rule unsatisfiable in CLI mode (only A7 registry probe is live).

## Problem statement

`tools/research-arch-v23/cli.mjs` runs in a standalone Node process. It does NOT have access to the Claude Code in-session MCP-client surface (`mcp__deepwiki__*`, `mcp__repomix__*`, `mcp__perplexity__*`, `mcp__exa__*`, `mcp__firecrawl__*`, `mcp__tavily__*`). As a result, when invoked standalone:

- A1 perplexity_sonar → skipped (no mcpClient)
- A2 exa_neural_search → skipped (no mcpClient)
- A3 firecrawl_structured_crawl → skipped (no mcpClient)
- A4 tavily_curated_search → skipped (no mcpClient)
- A5 cognition_deepwiki → skipped (no mcpClient)
- A6 repomix_ingest → skipped (no mcpClient)
- A7 authoritative_registry → live (uses gh CLI + npm view directly)

Only A7 is live in CLI standalone mode → live_angles=1 → fails sca-v23 §2.1 ≥3-angle convergence rule.

## W441.6 partial mitigation (THIS commit)

CLI now defaults `--min-angles` to `1` (was implicitly higher in earlier drafts), making A7-only registry-triage the documented CLI default behavior. Operators wanting full convergence MUST either:

1. Run via orchestrator-mode (Claude Code session calls `convergeAudit()` directly with `options.mcpClient` populated), OR
2. Wait for W442 standalone MCP-client wiring (this doc).

A startup-warning prints to stderr when `--min-angles < 3` (without `--dry-run`) directing operators to this carry-forward doc.

## Recommended W442 implementation

Per W441-RESEARCH-HARNESS verdict (`docs/architecture/W441-RESEARCH-HARNESS/HARNESS-COMPARISON-VERDICT.md`): install `pip install agent-framework-claude` (microsoft/agent-framework v1.6.0 python). The Microsoft Agent Framework ships a first-party Claude SDK wrapper with a native `MCPClient` class that runs standalone in Python (no Claude Code session required).

## Related W441.5 schema extension (THIS commit)

The sca-v23 schema `codex_verdict` property was refactored to `oneOf [invoked-shape, opt-out-shape]`:

- **Invoked shape**: `model: "gpt-5.5"`, `round: 1-3`, `verdict ∈ {APPROVE, REVISE, REJECT, BLOCK}`, `log_path: string`
- **Opt-out shape**: `model: null`, `round: 0`, `verdict: "SKIPPED"`, `log_path: null`, `rationale: string` (required)

This closes the W441.5 codex r2 REVISE blocker — the opt-out sentinel emitted when `codexAdversary` callback is not provided (e.g., standalone CLI mode without orchestrator) is now schema-valid.
