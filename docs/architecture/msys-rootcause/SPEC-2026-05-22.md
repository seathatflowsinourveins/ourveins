```
| Rank | Hypothesis            | Evidence cite | Predicted observable        | Falsifiable by             |
| P0   | CRLF stash-restore    | Stream B §X   | hash-delta with CRLF↔LF flip| diff bytes show line-end   |
```

**Codex round 1 gate**: validates ranking. NEEDS-REVISION if (a) any hypothesis lacks cite, (b) Falsifiable column is non-empirical, (c) priors don't match stream evidence.

### Phase 1 — `tools/precommit-msys-diag.mjs`

**Location**: `tools/precommit-msys-diag.mjs` (NOT in `.claude/hooks/**` → CR-2 ≤2KB does NOT apply; target ~5–8 KB).

**Interface**:
```
node tools/precommit-msys-diag.mjs [--hook <id>] [--tee <file>] [--json]
```

**Behavior** (deterministic, idempotent, read-only):
1. Snapshot SHA-256 + mtime of every tracked file via `git ls-files` (filtered by `.pre-commit-config.yaml` exclude regex).
2. For each hook in sequence: snapshot BEFORE → `pre-commit run <id> --verbose` with `PRE_COMMIT_LOG_FILE` → snapshot AFTER → compute hash-delta.
3. Emit report: filename · content-changed? · mtime-changed? · first-byte-of-diff · attribution-verdict.

**Report shape**:
```
┌─ Hook: msys-hooks-form (W335 P1-6) ─────────────────────────────┐
│ Files with content delta (n=N):                                   │
│   path/to/foo.md  CRLF→LF at byte 42                              │
│ Files with mtime-only delta (n=M):                                │
│   (none / list)                                                   │
│ ATTRIBUTION: msys-hooks-form caused {N content + M mtime} deltas  │
```

**Regression-test mode**: post-fix, future sessions re-run → expect zero deltas → asserts no regression.

**Codex round 2 gate**: (a) empirical confirms/falsifies Phase 0 ranking? (b) diagnostic itself touches tracked files (would invalidate)?

## 4. Phase 2 + Phase 3 components

### Phase 2 — Sandbox Reproducer

**Location**: `tmp/msys-sandbox/` (covered by `.pre-commit-config.yaml:19 tmp/.*` exclude — never enters this repo's index).

**Setup**:
```bash
mkdir tmp/msys-sandbox && cd tmp/msys-sandbox
git init
# minimal .pre-commit-config.yaml with ONLY msys-hooks-form
# copy tools/precommit-msys-hooks-form.mjs verbatim
# fixture .claude/plugins/cache/ subtree
pre-commit install
touch foo.md && git add foo.md && git commit -m "test"
```

**Bisect matrix**:

| Variable | Values | Pivot meaning |
|---|---|---|
| `core.autocrlf` | true · false · input | flip at true→false = CRLF root |
| Shell | Git Bash · cmd · pwsh | only-bash-fails = bash subprocess side-effect |
| Hook entry | `bash -c 'exec node ...'` · `language: system` direct node | direct-node-passes = entry shape root |
| `HOMEDIR` | sandbox-path · user-profile | only-worktree-HOMEDIR-fails = `.bash_history` write |
| File types | .md only · .py only · mix | .py-causes-flip = ruff-format theory revives |

**Output** — `docs/architecture/msys-rootcause/phase2-bisect-matrix.md` (variable × outcome table + verdict).

**Terminal verdicts**:
- **ISOLATED-REPRO**: root in hook/config layer → actionable in Phase 3 Case A
- **NO-REPRO**: root in runtime-state → actionable in Phase 3 Case B

**Codex round 3 gate**: matrix completeness + verdict-follows-from-cells.

### Phase 3 — Fix Implementation

**Case A — ISOLATED-REPRO, specific variable pinned** (most likely):

| Pinned root | Surgical fix |
|---|---|
| `core.autocrlf` causes hash flip | Add `.gitattributes`: `* text=auto eol=lf` (project-wide LF) OR scoped `*.mjs *.md text eol=lf` |
| `bash -c 'exec node ...'` writes `.bash_history` | `.pre-commit-config.yaml` entry → `language: system` direct `node` (drops bash subprocess) |
| Symlink/junction loop in walk() | Tighten skip-list in `tools/precommit-msys-hooks-form.mjs` `walk()` to not follow symlinks past depth N |
| Pre-commit framework hash-scope | Add `pass_filenames: true` + narrow file filter (framework hashes only staged) |

**Case B — NO-REPRO (runtime-specific state)**:
- Investigate this runtime's state during commit: process tree snapshot, mtime audit, pre-commit cache contents
- Candidates: (1) concurrent W362c session stash interference; (2) background MCP server touching tracked path; (3) pre-commit cache staleness
- Fix: serialize commits per worktree (`flock` / marker), `pre-commit clean` pre-commit, OR git config tweak — but pick **exactly one** single-variable fix
- **Timebox**: 90 min wall-clock for runtime-state investigation. If root is not pinned to a SINGLE variable by then, branch to Case C (PARTIAL-WIN escalation) — do NOT compound multiple Case-B fixes (flock + cache-clean + git-config) in this plan. Multi-variable Case-B fixes are explicitly deferred to a follow-up wave to prevent sprawl beyond a single implementation plan.

**Case C — Upstream framework bug (escalation from EITHER Case A or Case B)**:
- Triggered when: (i) Case A bisect pins a variable BUT no local fix is in our layer (e.g. pre-commit framework's hash-scope is fundamentally wider than staged files and that's their design), OR (ii) Case B runtime-state investigation finds the root is upstream framework behavior interacting with Git-for-Windows quirks we can't patch locally.
- File issue at `pre-commit/pre-commit` GitHub with isolated repro from Phase 2.
- Keep W348 escape hatch as documented operator-sanctioned workaround (codify rationale in audit doc).
- **PARTIAL-WIN ship**: diagnostic + sandbox + codified-rationale; no surgical local fix.
- Codex round 5 (wave-close) skipped since there's no fix-commit to gate; round 4 ADV concludes the pipeline.

**Patch invariants**:
- ≤30 LOC net delta across `.pre-commit-config.yaml` + hook + `.gitattributes`
- Reversibility note in audit doc (one-line revert command)
- No new top-level config files unless required
- Acceptance: post-fix diagnostic reports zero content-deltas for `msys-hooks-form`

**Codex round 4 ADVERSARIAL** — three independent prompts (not one combined):
- **Angle 1 (correctness)**: "Does this fix address the empirical root cause from Phase 1/2 evidence, or is it patching a downstream symptom?"
- **Angle 2 (side-effects)**: "What other gates / git operations / shell scripts could be affected? Scan all 9 pre-commit hooks, `.gitignore`, `tools/eee.ps1` env vars."
- **Angle 3 (upstream-bug-or-ours)**: "Is this fix in the right layer? If root is upstream framework, our patch is symptom-treatment; if our config, fixing here is correct."

Any NEEDS-REVISION → fix → re-run round 4 once. 2× NEEDS-REVISION on same angle → Sonnet 4.6 tie-break per W331.
